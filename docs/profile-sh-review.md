# Ревью `profile.sh` — замечания

> Готово к переносу в `docs/` после выхода из Plan mode (предлагаемое имя файла: `docs/profile-sh-review.md`, дата: 2026-10-31).

## Критичные баги

1. **`--min` не соответствует своему описанию.** В `--help` написано `Install base packages, oh-my-zsh, tmux, aliases only`, но в `COMPONENT_STATE=(N Y Y N N ...)` для min-режима tmux (компонент 4) выключен.
2. **`bootstrap_deps` ломается на RHEL-семействе.** Там группа называется `wheel`, а не `sudo`: `usermod -aG sudo "$USER"` упадёт, а `grep -qw sudo` по списку групп не найдёт ничего. В `main()` это учтено (`getent group wheel`), а в `bootstrap_deps` — нет.
3. **`--dry-run` всё равно меняет систему.** В `main()` порядок: `detect_distro` → `bootstrap_deps` → `show_interactive_menu` → проверка `DRY_RUN`. То есть `bootstrap_deps` успевает поставить пакеты и вписать NOPASSWD-судоерс до того, как dry-run отработает. Проверку `DRY_RUN` нужно поднять выше.
4. **Ассеты lazygit на ARM называются `arm64`, а не `aarch64`.** `ARCH_SUFFIX="aarch64"` подставляется в URL `lazygit_${VER}_Linux_aarch64.tar.gz` — на ARM ссылка всегда 404 (спасает только `check_url_exists`, но установка не работает).
5. **Фолбэк-поиск npm в `install_nvim_config` ничего не находит.** `find ... -name npm -type f` — а `~/.nvm/versions/node/*/bin/npm` это симлинк на `npm-cli.js`. Нужен `-xtype f` или `-type l`.
6. **`sudo rpm -i` не умеет апгрейд.** При повторном запуске с новой версией bottom установка упадёт («already installed»). Нужно `rpm -U` или `dnf install /tmp/bottom.rpm`.

## Безопасность

7. **Безусловный `NOPASSWD:ALL` — очень агрессивно.** `bootstrap_deps` молча выдаёт пользователю бессрочный sudo без пароля. Дополнительно:
   - файл в `/etc/sudoers.d/` создаётся через `> ...` в umask окружения → нужен явный `chmod 0440`;
   - нет валидации через `visudo -cf` — синтаксическая ошибка может отрубить sudo целиком;
   - имя файла `${USER}`: если в логине есть точка (`john.doe`), sudo **игнорирует** такой файл в sudoers.d — entry не работает;
   - `su -c "... > /etc/sudoers.d/..."` — кавычки и подстановка внутри su требуют внимательной проверки.
8. **`~/.oh-my-zsh` удаляется `rm -rf` без бэкапа** при каждом запуске (в отличие от `.zshrc`, который бэкапится через `backup_config`).
9. **`~/.vimrc` тянется с ветки `main` GitHub без фиксации версии** — конфиг может измениться под ногами. Стоит закрепить за тегом/коммитом или хотя бы предупреждать.

## Надёжность / Bash-нюансы

10. **`cmd || log_error` отключает `set -e` внутри всей функции.** Если функция вызвана слева от `||`, незащищённые команды внутри не абортят скрипт, а «проваливаются» дальше. Яркий пример — tarball-фолбэк в `install_bottom`: там `curl`, `tar`, `sudo install` без `if !` — при битом скачивании tar распакует мусор и может появиться битый `btm`.
11. **Интерактивное меню сломается при `curl ... | bash`.** `read -r input` читает stdin, а stdin — это пайп. Нужно `read -r input < /dev/tty`.
12. **`install_nvm` не идемпотентен.** Блок `export NVM_DIR=... / nvm.sh` дописывается в `~/.zshrc` при каждом запуске без grep-проверки (в отличие от блоков uv/алиасов) → дубли строк.
13. **`sudo -v` кэширует пароль ~15 минут**, установка может идти дольше — посреди `dnf groupinstall` скрипт зависнет на промпте. Решение: фоновый цикл `while true; do sudo -v; sleep 60; done &`.
14. **Фиксированные имена в `/tmp`** (`/tmp/lazygit.tar.gz` и т.д.) — коллизия при параллельном запуске / предсказуемые пути. Безопаснее `mktemp -d`.
15. **`git pull --ff-only` в `install_nvim_config`** при дивергенции вернёт ошибку, но (из-за п.10) скрипт залогирует «Neovim config updated» — проверять результат явно.

## Мелочи

- `check_url_exists` использует `--head` — часть CDN/редиректов иначе отвечает на HEAD; надёжнее скачать и проверить реальный файл.
- `pkg_name` возвращает несколько пакетов одной строкой (`python3-full python3-venv python3-pip`), а `resolved+=($resolved_name)` без кавычек полагается на word-splitting — работает, но хрупко: стоит прокомментировать, иначе кто-нибудь «починит» кавычками и сломает.
- `alias du='duf'` и `alias grep='grep --colour=always'` меняют поведение стандартных утилит в скриптах/пайпах — вопрос предпочтений, но нестандартно.
- `/opt/nvim-*` накапливает каталоги старых версий (симлинк обновляется, диски нет) — добавить очистку прежних версий.
- Логи `$HOME/profile_install_*.log` накапливаются без ротации.
- Скрипт целиком zsh-центричный (`.zshrc`, omz), вызывает `chsh` — bash-only пользователи не покрыты (принятое решение, просто зафиксировать в README).

## Порядок исправления

1. Пункты 1–6 (реальные баги, ломают функциональность).
2. Пункт 7 (sudo-безопасность: `visudo -cf`, `chmod 0440`, корректное имя файла, спросить подтверждение на NOPASSWD).
3. Пункты 10–12 (устойчивость и идемпотентность).
4. Остальное — по мере возможностей.
